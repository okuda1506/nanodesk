# Mac validation for the desktop preview

Use an Apple Silicon MacBook Air M3 with macOS 15 or later. Record the macOS and Xcode versions and the tested commit. Build and run the **NanoDesk** scheme on **My Mac** following the [README](../README.md#run-the-desktop-preview).

- [ ] Launch from Xcode and show the device from the NanoDesk status item. Confirm the front faces the viewer and the window has no border, title, background, drop shadow, floor or extra UI. Repeat over a light Finder window, dark content and the desktop wallpaper. Check outlines for black and white fringes at Retina scale.
- [ ] Use the housing to turn through 360° horizontally and vertically. Inspect the rear camera, both sides, top Hold switch and bottom ports at 45° and at full rotation. Check stable pivot, no clipping and no release inertia. Reset from the menu and by double-click.
- [ ] Drag the front wheel. It should remain reserved. Shift-drag the wheel and drag the same region from the rear to verify body rotation. In **Click Through** mode, verify that another app underneath receives clicks and that the menu can restore interaction.
- [ ] Option-drag between displays with different scale factors. Enlarge and shrink with Command-scroll, pinch and the menu. Restart and verify retained position, size, layering and click-through. Disconnect the display and check that the device is still fully visible. Test show, hide, always on top and quit.
- [ ] Compare front and approximately 45° screenshots to the approved [front](../assets/renders/tone_review/front.png) and [45° render](../assets/renders/tone_review/front_45.png). Capture rear and side angles too. Check silhouette, silver gradient, dark wheel and screen, and the absence of narrow bright reflection bands. Use similar apparent size and record differences in reflection, exposure and tone mapping before changing app lighting.
- [ ] Check rotation and idle responsiveness in Instruments if the renderer stutters or keeps drawing while hidden. Capture Xcode errors, missing entity names or the startup alert if the model fails to load.

Record local results in [findings](RISKS_AND_FINDINGS.md). If the desktop shows a rectangle, test the zero-alpha clear and layer compositing before adjusting lighting or editing the asset.

## Retest trackpad pinch

1. In System Settings → Trackpad → Scroll & Zoom, enable **Zoom in or out**. In NanoDesk, turn off **Click Through** and select **Reset Size**. Put the pointer on the model, then spread and pinch two fingers. Expect smooth expansion and contraction without Command and no jump or extra step on release. Repeat with Finder frontmost and NanoDesk above it. NanoDesk should resize without taking focus from Finder.
2. Confirm Command plus two-finger scrolling still resizes. Also test body drag, Option-drag and **Increase Size**, **Decrease Size**, and **Reset Size** in the status menu.
3. If pinch still fails, set Xcode source breakpoints in `DeviceCanvas.handlePinch(_:)` and `DesktopWindowController.zoom(by:)`. Check `gesture.state`, `gesture.magnification` before reset, and `self.window?.isKeyWindow` in the canvas. A nonzero pinch should reach both breakpoints. Disable the breakpoints before assessing motion.
4. To isolate the original failure, run the pre-fix build (`35f0ddf`) with a breakpoint in `DeviceCanvas.magnify(with:)` and repeat the Finder test. If neither baseline callback nor new recognizer receives input, use a temporary `NSEvent.addLocalMonitorForEvents(matching: .magnify)` in the debug build and return the event unchanged. Inspect `event.window` against the NanoDesk panel. An event addressed to the panel with no canvas callback points to view routing. If there is no event for the panel, repeat after temporarily making it key in the debugger (`self.window?.makeKey()` from `DesktopWindowController`). If needed, compare a separate debug-only run with an activating panel. An event arriving only after a focus change implicates panel event delivery. Record the key state, app activation and which callbacks fire, then remove temporary diagnostics.

## Mac validation for the music flow

Use the Apple Silicon Mac and the NanoDesk scheme. The previous desktop build was exercised on a MacBook Air M3 with macOS 27.2.1 and Xcode 27.2. Record the commit and versions for this music build separately.

1. Quit any previous build, then build and run. Confirm the front display shows a dark navy Japanese menu with a blue selection at launch, before opening Music or responding to Automation. With Click Through off, click the center button and verify that the header changes to **ミュージック**. Compare front, oblique and rear views. Text should stay on the display, follow rotation, and be hidden at the rear. Check the bezel, aluminum and transparent backdrop.
2. Trace clockwise and counterclockwise on the wheel. Check the direction, the ±π seam, stopping at both ends, no movement on a tiny jitter, and no click after a drag. Confirm that center opens **ミュージック** and then **曲**. Test the rear wheel region as a housing drag, and test Shift-drag and Option-drag.
3. Use the locally downloaded, purchased track already registered in Music. Close Music before the first library attempt. Open **曲**, approve the Automation prompt, and confirm the track appears without giving NanoDesk an audio file or a path.
4. Select the track with center. Confirm that Music plays audible audio and **再生中** shows the title, artist and progressing elapsed time/bar. Check artwork when available and the fallback when absent. Test the bottom button twice and check pause and resume in Music. With one track, both adjacent-track buttons should leave it playing without restarting. With multiple tracks, test both directions and both end stops.
5. Press MENU on **再生中**, **曲**, and **ミュージック** and verify the previous screen and selection. Confirm rotation, Option-drag, Command-scroll, status controls and saved placement remain functional.
6. In System Settings → Privacy & Security → Automation, disable **Music** under **NanoDesk**. Open **曲** and check the Japanese permission message and return via MENU. Re-enable the switch, reopen **曲**, and verify playback. If no prompt/switch appears in the signed app, record the signing configuration and the in-app error. Check Apple Events from the bundled app itself because Terminal automation permission is separate.
7. With a test library of zero songs, confirm the empty message. When a selected track is unavailable or fails in Music, confirm the app stays on **曲** with a reason. Quit Music during playback and check that status polling does not reopen it.
